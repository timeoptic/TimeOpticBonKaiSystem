# POS ขายกรอบแว่นกับคอนแทคเลนส์จากคลัง — ตัดสต็อกจริง

สถานะ: ผู้ใช้อนุมัติแบบในแชต 2026-09-18 · ทำบน local ก่อน ยังไม่ขึ้น Hostinger

## ปัญหา

หน้า `/pos` ขายจาก `pos_items` (migration 033) ซึ่งแยกจากคลังโดยตั้งใจ — ขายกรอบหรือคอนแทคเลนส์
ผ่าน POS จึงไม่ตัดสต็อก ยอดในคลังไม่ตรงของจริง ร้านต้องการให้กรอบแว่นกับคอนแทคเลนส์ที่ขาย
หน้าร้าน ดึงจากคลังและตัดสต็อกจริง ของอื่นขายแบบเดิม

## การตัดสินใจของผู้ใช้

1. ตัดสต็อกเฉพาะ **กรอบแว่น (Frame)** กับ **คอนแทคเลนส์ (ContactLen)** — แว่นกันแดด อุปกรณ์เสริม
   น้ำยา บริการ ยังขายจาก `pos_items` ไม่ตัดสต็อก
2. การ์ด 3 ใบบนหน้า = เลือกแหล่งค้นหา: **ขายกรอบแว่น** · **ขายคอนแทคเลนส์** · **สินค้าอื่น / บริการ**
   บิลเดียวปนได้ สลับการ์ดแล้วบิลไม่หาย แถวชิปหมวดหมู่เปลี่ยนตามการ์ด
3. ตัด **ตอนบันทึกบิล** ไม่ว่าส่งมอบวันนี้หรือไม่ · **ยกเลิกบิล (void) = คืนเข้าคลังอัตโนมัติ** ·
   ของหมด = ใส่บิลไม่ได้
4. รายการใน `pos_items` ที่ซ้ำกับคลัง (คอนแทคเลนส์ `PosCtl%` 19 ตัว และ `EYW-0003` "กรอบแว่น")
   **ซ่อนในโค้ด** ไม่แก้ฐาน — บิลเก่ายังเปิด/พิมพ์ได้
5. หน้าตาตามภาพที่ผู้ใช้ให้มา · ไม่มีคอลัมน์ส่วนลด (ระบบยังไม่มีส่วนลดรายบรรทัด) · ช่องและ
   พฤติกรรมอื่นของแผงขวาเหมือนเดิม

## ไม่แตะ schema

`pos_sale_items.product_id` (FK → `products`) มีอยู่แล้วตั้งแต่ก่อน 033 — แถวที่มาจากคลังเก็บ
`product_id` ตรงนั้น `pos_item_id` เป็น NULL · ข้อมูลการตัด (`stock_idem_key`, ล็อตที่ตัด) อยู่ใน
`item_meta` ของแถว

## API (`api/routes/pos.php`)

- `GET /api/pos/stock-products?type=Frame|ContactLen` — สินค้าประเภทนั้นในคลังพร้อม `on_hand`
  (ผลรวม `remaining_qty` ของล็อตที่เหลือ > 0) ราคา `base_selling_price` แบรนด์ สี/ค่าสายตาจาก
  `attributes` · คอนแทคเลนส์ได้ `pos_fields` ช่อง "ข้าง" (R / L / ทั้งสองข้าง บังคับ) นิยามเดียวกับ
  ของ `PosCtl%` เดิม แต่ไม่มีช่องค่าสายตา เพราะสินค้าในคลังแยกตามค่าสายตาแล้ว · อ่านอย่างเดียว
- `GET /api/pos/products` — ไม่เปลี่ยน (เทสต์ 80 ตรึงรายการครบ 41 ตัว) · การซ่อน `PosCtl%` กับ
  `EYW-0003` ทำที่หน้าเว็บ ตอนแสดงการ์ด "สินค้าอื่น / บริการ"
- `POST /api/pos/sales` — รายการรับ `stock_product_id` (แทน `product_id`) ได้ · ตรวจว่าเป็น
  Frame/ContactLen และยังอยู่ · ภายใน transaction เดียวกับการเขียนใบ และ **ก่อน** INSERT หัวใบ เรียก
  `StockClient::post('/stock/issue')` ทีละรายการ ด้วย `source = 'pos'`
  - `source` ไม่ใช่ `frontdesk` → ฝั่งคลังล็อกล็อตแล้ว **ปฏิเสธถ้าของไม่พอ** (`MAY_GO_SHORT`
    มีแค่ frontdesk ซึ่งยอมให้ติดลบสำหรับงานเคส)
  - PDO ใช้ร่วมกัน `Db::tx` ซ้อนกันได้ → ตัดไม่ผ่านรายการเดียว ทั้งใบ rollback ทั้งสต็อกและใบ
  - `idem_key = pos-<client_ref|pos_no>-<ลำดับแถว>-<sku>` คงที่ต่อการกดซ้ำ
  - `reference_doc = pos_no` → หน้าความเคลื่อนไหวของคลังเห็นเลขบิล
  - โหมดคลังไม่ใช่ live → ปฏิเสธบิลที่มีของจากคลัง พร้อมเหตุผล
- `POST /api/pos/sales/:id/void` — คืนทุกแถวที่มี `stock_idem_key` ด้วย `/stock/return`
  (`reverses_key`) ใน transaction เดียวกับการเปลี่ยนสถานะ

## หน้าเว็บ

- `pos/page.jsx` — การ์ดโหมด 3 ใบ · การ์ดค้นหา + ชิป · ตารางบิล + ล้างรายการ + เพิ่มรายการด้วยตนเอง
  (คือ `pos_items` `is_custom`) · แผงขวาหน้าตาใหม่ ฟังก์ชันเดิม
- `ProductPicker` รับสินค้าจากแหล่งที่เลือก โชว์คงเหลือ ของหมดกดไม่ได้
- `cart.js` — แถวจากคลังมี `stock: true`, `stock_product_id`, `on_hand` · รวมแถวแยกตามแหล่ง ·
  `validateCart` เตือนเมื่อจำนวนเกินคงเหลือ · `toItemsPayload` ส่ง `stock_product_id`
- แผงค่าสายตาโผล่เมื่อมีคอนแทคเลนส์ ทั้งจาก `pos_items` เดิม (ช่อง power) และจากคลัง (ContactLen)
